引数なしの `/loop` で回るメンテナンスループ。新しい作業を勝手に始めないこと。

1. 会話の中にやりかけの作業があれば、それを続ける。
2. 現在のブランチに PR があれば面倒を見る。
   - CI が赤ければ失敗したジョブのログを取得し、原因を診断して最小限の修正を push する。
     エラーの抑制で通してはいけない。
   - 新しいレビューコメントがあれば対応し、スレッドを解決する。
   - base ブランチとコンフリクトしていれば `main` を取り込んで解消する。
3. PR がない、または PR が全部緑なら `/verify` を1回走らせ、赤ければ直す。
4. すべて緑で保留が何もなければ、**1行だけ**「異常なし」と報告して終わる。

push や `make deploy` のような取り消しにくい操作は、会話の中で既に承認された作業の
続きである場合にのみ行う。デプロイは特に、明示的な依頼なしに実行しないこと。
